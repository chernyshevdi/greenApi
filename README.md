# Telegram Chat — тестовое задание «Фронтенд разработчик React»

Минимальный веб-чат для отправки и получения текстовых сообщений в **Telegram** через
[GREEN-API](https://green-api.com/telegram/docs/). Внешний вид — по образцу
[web.telegram.org](https://web.telegram.org/).

> Задание допускает Telegram вместо MAX, поэтому интеграция сделана для Telegram.

## Возможности

- Вход по `idInstance` и `apiTokenInstance` из личного кабинета GREEN-API.
- Создание чата по номеру телефона получателя.
- Отправка текстового сообщения (Enter — отправить, Shift+Enter — перенос строки).
- Получение ответов в чате (long-poll `receiveNotification`).
- Статусы исходящих (отправляется / отправлено / ошибка) и повторная отправка.
- Список чатов с превью, временем и счётчиком непрочитанных; адаптив под мобильные.

Только текстовые сообщения, без медиа, групп и прочего — как требует задание.

## Быстрый старт

Нужен Node.js `^20.19` или `>=22.12`.

```bash
npm install
npm run dev
```

Откройте адрес из вывода команды (по умолчанию http://localhost:5173).

### Что нужно от GREEN-API

1. Зарегистрируйтесь в [личном кабинете](https://console.green-api.com/registration).
2. Создайте инстанс (подойдёт бесплатный тариф Developer) и дождитесь активации.
3. Авторизуйте инстанс в Telegram: в приложении Telegram откройте *Настройки → Устройства →
   Подключить устройство*, в кабинете нажмите «Получить QR» и отсканируйте код.
4. В параметрах инстанса возьмите `idInstance`, `apiTokenInstance` и `apiUrl`.
5. **Включите входящие уведомления.** В кабинете, раздел «Webhooks» → Change: «Receive webhooks
   on incoming messages and files» = Yes (`incomingWebhook`), а `webhookUrl` оставьте пустым.
   Пока уведомления выключены, ответы получателя не приходят и ошибки при этом нет. Приложение
   проверяет эти настройки и показывает плашку над списком чатов, если с ними что-то не так
   ([SetSettings](https://green-api.com/telegram/docs/api/account/SetSettings/)).

### Как пользоваться

1. Введите `idInstance` и `apiTokenInstance`. `apiUrl` по умолчанию `https://api.green-api.com`;
   если в кабинете указан другой адрес, откройте «Дополнительно» и впишите его.
2. Нажмите «Новый чат», введите номер получателя в международном формате (например,
   `79876543210`, только цифры), создайте чат.
3. Напишите сообщение и отправьте его. Получатель должен ответить в Telegram — ответ появится в
   чате.

## Используемые методы GREEN-API

| Метод | Для чего |
|---|---|
| [`SendMessage`](https://green-api.com/telegram/docs/api/sending/SendMessage/) | отправка текстового сообщения |
| [`ReceiveNotification`](https://green-api.com/telegram/docs/api/receiving/technology-http-api/ReceiveNotification/) | получение входящих (long-poll) |
| [`DeleteNotification`](https://green-api.com/telegram/docs/api/receiving/technology-http-api/DeleteNotification/) | подтверждение обработки уведомления |
| [`CheckAccount`](https://green-api.com/telegram/docs/api/service/CheckAccount/) | получение `chatId` по номеру телефона |
| [`GetStateInstance`](https://green-api.com/telegram/docs/api/account/GetStateInstance/) | проверка кредов и состояния инстанса при входе |
| [`GetSettings`](https://green-api.com/telegram/docs/api/account/GetSettings/) | проверка, что включены входящие уведомления и пуст `webhookUrl` |

`CheckAccount`, `GetStateInstance` и `GetSettings` — сверх двух методов из задания, и вот зачем:

- **`CheckAccount`.** `chatId` в Telegram не вычисляется из номера. Сообщение можно отправить на
  `номер@c.us`, но ответ придёт с настоящим `chatId` (например, `10000000`) и создал бы отдельный
  чат. Поэтому `chatId` запрашивается один раз при создании чата.
- **`GetStateInstance`.** Неверные креды обнаруживаются при входе, а не при первой отправке, и
  пользователь видит понятную причину (например, инстанс не авторизован в Telegram).
- **`GetSettings`.** Выключенные входящие уведомления не дают ошибки: очередь просто пуста.
  Проверка настроек позволяет объяснить пользователю, почему ответы не приходят.

## Архитектура

Проект построен по [Feature-Sliced Design](https://feature-sliced.design/): слой импортирует только
слои ниже себя, слайсы одного слоя изолированы друг от друга. Это проверяет ESLint
(`eslint-plugin-boundaries`, см. `eslint.config.js`).

```
src/
  app/        инициализация: стор, сохранение состояния, провайдеры, стили
  pages/      login, chat — экраны
  widgets/    chat-list, chat-window — крупные блоки интерфейса
  features/   auth, create-chat, send-message, receive-messages — пользовательские сценарии
  entities/   session, chat, message — модели и «глупые» компоненты
  shared/     api (клиент GREEN-API), lib, ui
```

Стек: React 19, TypeScript, Redux Toolkit, Vite, Vitest + Testing Library, CSS Modules.

Как работает получение сообщений: цикл `receiveNotification` → разбор (`parseIncomingMessage`
пропускает только входящие текстовые) → запись в стор → `deleteNotification`. Повторная доставка
того же уведомления не дублирует сообщение. Нетекстовые уведомления только удаляются из очереди.
При сетевых ошибках цикл делает паузы 1 → 2 → 5 с, при 401/403 останавливается и возвращает на
страницу входа.

## Хранение данных и безопасность

- **Токен** (`apiTokenInstance`) хранится в `sessionStorage`: живёт только в текущей вкладке и не
  остаётся на диске после её закрытия.
- **Чаты и сообщения** хранятся в `localStorage`, потому что GREEN-API не возвращает историю.
  Чаты привязаны к `idInstance`; при входе в другой инстанс форма предупреждает, что старые чаты
  будут удалены. Кнопка «Выйти» очищает всё.
- Это приложение работает без собственного сервера, поэтому токен доступен JavaScript страницы.
  Любой скрипт на странице (например, при XSS) мог бы его прочитать. В продакшене токен должен
  храниться на бэкенде, а браузер — обращаться к нему.

## Допущения и ограничения

- Статус «отправлено» означает, что GREEN-API принял сообщение в очередь на отправку (так отвечает
  `SendMessage`), а не что оно доставлено.
- Уведомления в очереди читает один клиент. Если открыть приложение в двух вкладках или параллельно
  работает другой потребитель очереди, они будут «забирать» уведомления друг у друга.
- Номер вводится в международном формате цифрами: `8…` в `7…` не преобразуется.
- На бесплатном тарифе действует лимит на проверки `CheckAccount` (100); частые проверки разных
  номеров могут привести к ограничению со стороны Telegram.
- Текстовые сообщения принимаются в виде `textMessage` и `extendedTextMessage` (текст со
  ссылкой); ответ через «Ответить» в Telegram приходит как `textMessage` и тоже показывается.
- Инстанс в статусе `suspended` (ограничена отправка) пускается в приложение: получение работает.

## Сборка и деплой

`npm run build` создаёт статический сайт в `dist/`, его можно выложить на любой статический хостинг
(Vercel, Netlify, GitHub Pages и т. п.). API GREEN-API отдаёт CORS-заголовки
(`Access-Control-Allow-Origin: *`), поэтому прокси не нужен.

## Тесты

`npm test` — модульные и компонентные тесты (API-клиент с замоканным `fetch`, парсер уведомлений,
редьюсеры, поллинг, сохранение состояния, формы и экраны). Живой GREEN-API в тестах не
используется.
